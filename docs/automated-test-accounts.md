# 20アカウントの自動投稿テスト

| 設定 | 値 |
| --- | --- |
| 対象DB | pgweb.akatukii.com の pet_yoyo |
| アカウント | yoyo-test-01@example.invalid ～ yoyo-test-20@example.invalid |
| ペット名 | テスト01 ～ テスト20 |
| 投稿時刻 | 日本時間の毎日09:00・21:00 |
| 投稿先 | https://api.akatukii.com/posts |
| 定期実行 | Codexの「テスト20アカウントの朝夜投稿」（ID: 20） |
| 初回 | 2026-09-10、朝枠20件を事前に実行済み。当日09:00はスキップする |

## 1. 初期登録

`backend/scripts/seed_automated_test_accounts.sql` をpgwebで実行する。
既存の `users`、`pets`、`user_active_pets`、`pet_experiences`、`pet_group_joins` を使い、テーブルの追加は不要。
20種類の既存群れへ1匹ずつ配置する。ステータスは初期値50、進化段階は0。
再実行時も経験値や現在の群れをリセットしない。

アカウントは自動投稿テスト専用で、パスワード欄はログインできない印にする。
実在するメールアドレス、通知先、課金情報は登録しない。
このテストはログインを行わないため、ログイン時だけに実行する旅立ち判定は対象外。
旅立ち・ペット再割り当てを別のテストで行った場合は、この固定20匹の運用をいったん停止して対象を見直す。

## 2. 定期投稿

プロジェクトのルートで実行する。Python標準ライブラリだけを使用する。

```sh
# 読み取りだけで、現在の枠の投稿予定を確認する。
python3 backend/scripts/automated_test_posts.py

# 本番のテスト20匹へ投稿する。通常の定期実行はこのコマンド。
python3 backend/scripts/automated_test_posts.py --apply
```

通常は09:00～20:59を朝枠、21:00～23:59を夜枠とし、00:00～08:59は投稿しない。
遅れて実行された場合は現在の枠だけ実行する。過去日の欠落や、21時以降に朝の欠落を埋める投稿は行わない。
`--slot morning` / `--slot evening` は初回確認専用で、当日の指定枠を消費する。

投稿はAPIからGoの既存処理を通す。そのため、投稿・給餌回数・経験値履歴・進化判定が通常どおり処理される。
DBトリガーを受け取ったPythonワーカーが、名詞抽出・埋め込み・群れのマッチングを実行する。
投稿だけでは毎時シミュレーションを起動しない。群れの移動・おみやげは既存の毎時処理に任せる。

## 3. 重複・失敗の扱い

日付・朝夜枠・アカウント番号を本文に記載し、投稿前にAPIの履歴と照合する。
同じ枠が投稿済みならスキップし、その日の投稿数が2件以上でもスキップする。
`backend/scripts/.automated-test-posts/` に送信状態と実行ロックを保存する。
このディレクトリはGit管理から除外する。

このスクリプトは**同じPC・同じ作業ディレクトリで1系統だけ**運用する。
APIにはサーバー側の冪等性キーがないため、別PCから同時に起動しない。
POST直前にpendingを書き、返答前に切断した場合は次の実行で投稿履歴を照合する。
履歴にも見つからない送信結果不明の投稿は自動再送せず、確認が必要なエラーとして報告する。
状態ファイルを消して再送しない。

Codexの定期実行には、時刻になった際にPC・アプリが起動し、ネットワークとこのディレクトリを利用できる必要がある。
アプリ停止・スリープ・利用上限・権限制約などで実行できなかった時の1日40件は保証しない。
通常成功時は通知せず、投稿失敗や対応が必要な問題が発生した時だけ知らせる。
停止はCodexの定期実行画面で「テスト20アカウントの朝夜投稿」を一時停止するか、元のタスクで停止を依頼する。

## 4. 検証結果

2026-09-10の初回は、20投稿・埋め込み20件・名詞抽出済み20投稿・マッチング済み20投稿・給餌イベント20件・加算経験値合計200をpgwebで確認。
macOS標準Pythonの可変桁の小数秒への対応を含め、以下の14テストが成功。

```sh
python3 -m unittest discover -s backend/scripts -p 'test_automated_test_posts.py' -v
```

検証には時間帯の境界、日次上限、重複、送信後の切断、状態ファイル消失時の照合、想定外のAPI応答を含む。
